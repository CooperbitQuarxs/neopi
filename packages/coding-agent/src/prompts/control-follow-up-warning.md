There is rarely a circumstance where you should queue instead of steer. In an automated environment where the target never yields (a software factory like this one), a queued message will very likely never reach this agent. The Captain has repeatedly seen agents misuse the control plane this way, biased by "queued = 0" in the state, which also means "steered = 0". About 95% of the time you want `steer`; otherwise interrupt with `send`. Your message was still queued. This is your warning; a second `follow_up` from you proceeds without it.
